# 背屏达人 4.0 · 安全与反编译代码审查报告

[应用详情](README.md) · [社区安全检查](../security/README.md) · [3.0 历史报告](security-3.0.md)

**结论：❗ 安全风险，暂停 4.0 APK 公开下载。** 部分写入已增加配对令牌，但状态和服务诊断读取未鉴权，会返回状态消息或用户配置的账号字段。定向代码审查与虚构数据隔离处理器测试确认该返回路径；未读取真实账号，未执行独立恶意 App 攻击。另有未鉴权状态修改的实机证据。按研究所收录规则限制该版下载，保留介绍、功能报告与宣传片，不授予安全通过标记。

这不表示应用具有恶意意图。服务只绑定本机回环，本报告没有发现默认局域网监听或互联网远程控制证据。

## BSF4-01 · 状态及服务诊断未鉴权读取

**位置**：`StatusServer.handle`、`PlaybackService.statusLine`、`ServiceFeed.refresh`。

鉴权仅覆盖 `/event` 和带 `tool` 或 `state` 的 `/status` 写入。无写入参数的状态读取及 `/feed` 诊断读取不经过令牌校验。`statusLine` 拼接状态消息；服务诊断拼接用户填写的 B 站 UID、粉丝数、更新时间或错误信息。

**证据**：隔离处理器使用虚构账号和消息，无凭证请求取得对应值。数据来自模拟状态；没有使用真实账号。代码的字段拼接和返回路径明确，未独立验证另一个 Android App 在所有系统配置下的可达性。

**影响与条件**：接口运行且调用方能连接本机回环时，未配对调用方可读取这些字段。UID 或消息可能关联使用者，写入私人内容也会被返回。回环限制缩小网络范围，不能替代应用层读权限。

**建议**：所有读取与写入均鉴权，诊断默认不返回账号及原始消息，提供显式开关；修复后使用独立未授权应用复测。

## BSF4-02 · 未鉴权的状态重置

**位置**：`StatusServer.handle` 的 `/quit` 分支。

分支在鉴权条件之外，调用 `pushStatus` 将状态改为空闲。实机无令牌请求得到 `idle`，随后读回状态为空闲；隔离处理器结果相同。证据支持状态干扰，不支持任意命令执行或系统控制的扩大描述。建议将此入口纳入鉴权和方法约束，复测缺失、错误及合法凭证。

## BSF4-03 · 外部广播缺少调用方约束

**位置**：清单的 `StatusReceiver`；`StatusReceiver.onReceive`。

接收器导出且无保护权限。代码核对 action，将三个文本字段分别截断到 40 字符，但未校验发送者，随后更新状态。长度限制不能替代认证。同机应用可能伪造状态；实际后台启动受 Android 版本与运行状态约束，未用独立攻击 App 验证。建议默认不导出，或为必要集成采用明确授权，增加频率与字段允许值限制。

## BSF4-04 · 请求总量与字段长度限制不足

**位置**：`StatusServer.acceptLoop / handle`。

连接读取超时 4 秒，声明正文超过 4096 时不读取正文；请求行和头部仍逐行读取，没有明确总长度与总期限。隔离检查中，合法虚构令牌的 32 KiB 字段进入状态设置函数，支持缺少统一字段长度限制的判断。可能造成内存压力或延迟合法请求；未在手机实施资源耗尽测试，不能声称手机必定崩溃。建议限制请求行、头部、字段、频率和总期限。

## BSF4-05 · 鉴权失败仍返回 HTTP 200

**位置**：`StatusServer.handle` 的统一响应写入。

实机缺失和错误令牌的写入请求均返回 HTTP 200，正文提示需要令牌；正确令牌正常写入。只检查 HTTP 状态的客户端可能误判成功。建议返回适当的 401/403 并校验业务结果。此协议问题单独不构成暂停下载的依据。

## 签名、敏感信息检查与测试局限

- APK v2/v3 签名完整性通过，证书为产品通用名称；不单独证明作者身份，未证明源码与 APK 可复现对应。
- 解包内容、关键字符串和 Gitleaks 扫描未发现硬编码凭据或明显个人/开发机器路径；不保证覆盖所有隐藏形式。
- 隔离处理器保留反编译控制流，将 Android 上下文与状态替换为虚构内存对象。为编译检查型异常，在 `parseInto` 声明补充 `throws IOException`；没有据此对非法编码异常处理作结论。
- 5 项隔离检查：无凭证诊断读取、无凭证写入拒绝、合法写入后的无凭证读取、无凭证重置、32 KiB 合法字段。这不是 Android 双应用攻击测试。
- Tenor 页面及媒体直链在手机连接阶段超时；电脑下载有效 GIF 后，本地转换为 29 帧并在应用播放。网络失败不能写成已证明解码器不支持该文件。

## 修改建议、可能风险与恢复下载条件

| 优先级 | 修改建议 | 风险与复核要求 |
| --- | --- | --- |
| 优先修复 | 状态读取、诊断、修改和退出统一认证，减少返回字段 | 排除未配对读取账号、消息及重置的路径 |
| 优先修复 | 关闭无保护广播或加入明确授权 | 未授权应用不能改变状态，合法集成仍可工作 |
| 稳定性改进 | 请求行、头部、正文、字段、频率和总时间设限 | 超长、慢速及连续输入响应有界，资源可恢复 |
| 协议改进 | 正确返回鉴权错误码，增加令牌随机长度和尝试限制 | 客户端不得把鉴权失败视为成功 |
| 补充验证 | 双应用、流量、媒体异常、深度待机和桥接端 | 为修复后的确切版本与哈希重新建证据 |
