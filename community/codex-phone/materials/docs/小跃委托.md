# 可选：内置小跃 → 手机本地 Codex

先完成主教程并验证 CLI 与 MCP。这里只增加普通任务委托，不修改厂商默认模型、不改受保护配置，也不使用厂商原生 GUI Agent / 8765 MCP。

实际流程：小跃的普通端侧执行工具 → 手机 `127.0.0.1:19094` → shell 身份的本地 Codex → 自己的模型 API 与手机 MCP → 小跃查询原编号结果。CLI 独立控屏不需要此桥接。

## 1. 部署并启动桥接

仍在分享包目录的 PowerShell 中，沿用主教程的 `$device`、`$phoneRoot`：

```powershell
adb -s $device shell "mkdir -p $phoneRoot/bridge $phoneRoot/bridge-assets"
adb -s $device shell "chmod 700 $phoneRoot/bridge $phoneRoot/bridge-assets"
adb -s $device push '.\optional\bridge.sh' "$phoneRoot/bridge.sh"
adb -s $device push '.\optional\task-progress.jq' "$phoneRoot/task-progress.jq"
adb -s $device push '.\optional\task-error.jq' "$phoneRoot/task-error.jq"
adb -s $device push '.\optional\client.py' "$phoneRoot/bridge-assets/client.py"
adb -s $device shell "chmod 700 $phoneRoot/bridge.sh"
adb -s $device shell "nohup /system/bin/sh $phoneRoot/bridge.sh --serve </dev/null >$phoneRoot/bridge/listener.log 2>&1 &"
```

只在尚未运行此服务时启动；不要对已有配对或正在执行的任务重复初始化。网络只监听手机 loopback，不能把监听地址改成 `0.0.0.0` 后公开使用。

让小跃用**自己的普通端侧 Python 执行工具**运行下面代码。这里的 Python 属于小跃可访问的执行环境，不是 ADB shell；不要求 ADB 能进入厂商 rootfs。

```python
import json
from pathlib import Path
import urllib.request

http = urllib.request.build_opener(urllib.request.ProxyHandler({}))
base = 'http://127.0.0.1:19094'
with http.open(base + '/health', timeout=3) as response:
    health = json.load(response)
assert health.get('ok') is True
target = Path.home() / '.local/share/stepneo-phone-codex'
target.mkdir(parents=True, exist_ok=True, mode=0o700)
with http.open(base + '/assets/client.py', timeout=3) as response:
    data = response.read(65536)
assert data.startswith(b'#!/usr/bin/env python3')
client = target / 'client.py'
client.write_bytes(data)
client.chmod(0o600)
print('桥接可达，客户端已保存；尚未配对')
```

如果当前版本的小跃没有这样的执行工具，或访问 loopback 被拒绝，应先停在这一步排查；不能靠更改一句聊天提示词保证接入。

## 2. 在朋友自己的手机重新配对

准备好小跃端代码后，在电脑开启一次五分钟配对窗口：

```powershell
adb -s $device shell "/system/bin/sh $phoneRoot/bridge.sh --pair-window"
```

随即让小跃的普通端侧 Python 工具运行以下代码。它生成独立随机客户端令牌并保存，**不会读取或接触模型 API Key**：

```python
import json
import os
from pathlib import Path
import secrets
import urllib.request

credential = Path.home() / '.local/state/stepneo-phone-codex/client.json'
credential.parent.mkdir(parents=True, exist_ok=True, mode=0o700)
if credential.exists():
    raise SystemExit('已有客户端凭据，请先用 doctor 检查，避免覆盖')
token = secrets.token_hex(32)
fd = os.open(str(credential), os.O_WRONLY | os.O_CREAT | os.O_EXCL, 0o600)
with os.fdopen(fd, 'w', encoding='utf-8') as stream:
    json.dump({'token': token}, stream)
http = urllib.request.build_opener(urllib.request.ProxyHandler({}))
request = urllib.request.Request(
    'http://127.0.0.1:19094/v1/pair',
    data=json.dumps({'token': token}).encode('utf-8'),
    headers={'Content-Type': 'application/json'},
)
try:
    with http.open(request, timeout=3) as response:
        result = json.load(response)
    assert result.get('paired') is True
except Exception:
    raise SystemExit('配对未确认；保留本地凭据，先运行 doctor 核对，不要重新生成令牌') from None
print('配对完成；令牌保存在客户端私有状态文件中')
```

这段首次配对示例未在朋友的新机上验证。若明确返回 `pairing_expired` 或 `pairing_closed`，且确认服务端尚未写入令牌，可保留同一个客户端令牌重新开窗并配对；结果不明时先检查，禁止直接删除双方状态反复尝试。

不要把 `client.json` 的内容交给模型、复制到聊天或分享给别人。模型 Key 在 Codex 自己的登录文件，桥接令牌在小跃自己的状态文件，两者用途不同。

## 3. 自检、提交一次、查询原编号

下面命令仍由小跃的普通执行工具在自身环境运行，不是在电脑 PowerShell 中执行：

```sh
python3 ~/.local/share/stepneo-phone-codex/client.py doctor
python3 ~/.local/share/stepneo-phone-codex/client.py run --request-id demo-phone-001 --prompt '只读取手机状态和当前 UI，简短概述，不点击、不输入。' --wait 4
python3 ~/.local/share/stepneo-phone-codex/client.py status demo-phone-001 --wait 4
```

`doctor` 只检查版本，不调用 Codex 模型 API；小跃自身理解和执行请求可能仍有它的正常模型用量。`run` 会调用朋友配置的模型服务。

实际任务使用新的唯一编号；同一任务 POST 一次后，反复短 GET 原编号即可。当前客户端单次等待最多六秒，HTTP 默认三秒；服务总期限为 600 秒、单任务并发。这些期限不是同一回事。GET 会返回状态、工具完成/失败数、最后工具、期限来源及剩余时间。

请求超时或结果不明时，**保留编号查询，不要换编号自动重投**。最终回答为空也不能判断“完全没有执行”；应结合进度和屏幕实际结果。截图用于模型感知，默认不进图库。

## 4. 保存普通说明和委托偏好

把同包 `optional/AMOO_README.txt` 作为普通文本，让小跃用正常文件工具保存到它自己的：

```text
~/.local/share/stepneo-phone-codex/README.txt
```

再通过正常记忆界面保存一条偏好：

> 当我要求交给手机本地 Codex 时，先读取 `~/.local/share/stepneo-phone-codex/README.txt`，使用已经配对的客户端提交一次任务，再查询原编号并报告实际结果。不要展示、读取到聊天或修改任何凭据。

本次普通说明与持久配对已在新聊天中验证可以复用。这是偏好委托，不保证所有聊天都强制进入 Codex。这里没有安装原生 OpenClaw Skill，也没有替换默认聊天后端。

## 恢复与自启状态

重启或系统结束服务后，先核对 19094 监听、旧 worker 和 `bridge/active`；确认没有在运行的任务后再恢复监听。保留配对和任务记录，不要为了恢复就删除 active 或重新配对。
