## 3. 定向代码检查

| 检查点 | 证据与结论 |
| --- | --- |
| 安装包结构 | 1 个 DEX，包含 arm64 原生库 `libEncryptorP.so`（本轮未反汇编审查）；前端是内置 HTML / JavaScript。未提供服务端代码 |
| 权限 | 清单包含网络、相册、相机、蓝牙、应用枚举与请求安装 APK 等权限，能力范围较广；权限声明本身不证明发生采集或滥用 |
| 实机权限状态 | 测试结束时相机、图片/视频、蓝牙扫描与连接均未授予；网络等普通权限已授予 |
| 组件 | 主页面为导出启动 Activity，包含深链入口；文件 Provider 不导出，允许按 URI 授权。ProfileInstallReceiver 受系统 DUMP 权限保护 |
| WebView | `WebContainerActivity` 禁用直接 file/content 访问、禁止混合内容和第三方 Cookie；调试开关受 debuggable 条件控制。存在 CapsuleBridge 与 AbilityMcp 原生桥，需要进一步验证导航来源及调用权限 |
| 网页链接 | 前端 `NC` 对发布地址检查 HTTPS 及 Step 域名允许列表；该前端检查不能代替服务端校验 |
| 后端访问 | 使用 Supabase 客户端。内置 JWT 的 role 为 anon，不是 service_role；客户端标识仍需配合服务端行级权限，当前未核验服务端策略 |
| 平台能力凭据 | manifest 含非空 apiKey，原生代码将其用于系统能力握手及后续调用。仅凭客户端代码不能确认公开分发范围或服务端绑定策略；不展示值，也未尝试跨应用使用 |
| 下载与升级记录 | 前端通过 URL 打开下载，并以本地记录保存下载版本。记录不等于系统已安装版本，升级提示尚未实测 |
| 统计与第三方代码 | 内含字节系统计 SDK，前端有 app_open 事件写入调用；实际发送字段、同意流程与服务端保存策略未抓包核验 |

Supabase 官方说明将 anon 视为客户端公开标识，但要求配合行级权限；不能据此推断其他平台的 apiKey 也可公开。[官方说明](https://supabase.com/docs/guides/database/secure-data)

本轮未做流量解密、越权请求、服务端探测或完整模糊测试，未上传第三方查杀服务。没有足够证据确认系统破坏或信息泄漏威胁，也没有足够证据宣称全部安全。

## 4. 修改建议与可能风险

| 修改建议 | 可能风险 / 待核事项 |
| --- | --- |
| 明确平台能力凭据可公开分发的范围和包名/签名绑定机制 | 若凭据可脱离应用复用，可能被冒用；目前未确认，需作者或平台说明 |
| 核验数据库与文件存储的行级权限及所有权校验 | 发布、删除、评分、评论及管理员操作不应只依赖前端；当前服务端权限未验证 |
| 精简不使用的相机、蓝牙及应用枚举能力 | 宽泛权限增加使用者理解成本与潜在暴露面；本轮未观察到这些权限被使用 |
| 对原生桥、外链与深链做来源限制测试 | 不可信页面能否接触系统能力仍需验证，反编译未完整还原导航方法 |
| 清楚说明统计数据、登录信息与公开内容的用途 | 登录、发布与统计会涉及数据传输，当前未独立核验实际上传字段和保留策略 |
| 将“下载过”与“已安装”区别展示 | 下载确认后取消、安装失败或手动更新可能使本地版本记录失真 |

当前仅作基础实机验证记录。APK 已上架；安全状态仍需按证据复核，不因能够运行而自动升级为 ✅。
