# 08 · 应用进阶：课程目录与管理后台

[课程首页](README.md) · [预览与测试](04-test.md) · [发布整理](07-release.md)

官方知识库用健身课程售卖说明用户端与后台协作。本课将它改为**免费课程目录**，先练字段、数据和权限；不做支付，不申请商户凭证。这是研究所改编练习，尚未实际构建验收。

## 这次做什么

用户查看三门虚构课程的名称、介绍与时长；管理端修改课程介绍。先画出“管理端保存 → 用户端看到变化”的流程。没有实际保存能力时明确标注演示，不用刷新后丢失的状态冒充持久保存。

## 分两步制作

1. 新建应用练习，让总控先列出页面、字段和数据保存方案。先用固定示例数据完成用户端列表与详情。
2. 页面正确后，再询问当前平台提供的存储与管理端认证能力；确认支持后添加后台。若需要额外申请服务凭证，停在界面练习，记录待接入项。

```text
创建一个免费健身课程目录，包含用户端列表、详情，以及 Web 管理后台。
先用三门虚构课程，只设课程名称、介绍和分钟数；不做支付、订单或外部连接器。
第一步只完成示例页面。第二步先说明平台支持的数据保存与管理员认证方案，再实现管理端编辑。
管理端修改后，用户端应读到同一条课程的新内容；不要把前端临时变量当成已保存数据库。
说明开发数据与正式数据如何区分，不假设发布后课堂数据自动存在。
```

## 验收这条数据流程

| 操作 | 要观察的结果 |
| --- | --- |
| 修改一条课程介绍并保存 | 用户端显示对应课程的新介绍 |
| 重新打开页面 | 已保存内容仍在；若仅演示，应明确提示 |
| 用非管理用户访问编辑入口 | 后端拒绝越权操作；隐藏按钮不能代替权限校验 |
| 输入空名称或无效时长 | 提示原因，原有课程不被错误覆盖 |

官方账号登录和作品内用户登录是两回事。有登录页面也不代表数据已经隔离。如果还没有可验证的认证方案，就不公开管理端。

完成条件：留下正常保存、重新读取、无效输入与权限检查四条记录；不支持的部分标“待接入”。之后阅读[发布整理](07-release.md)。
