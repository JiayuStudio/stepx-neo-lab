# 09 · 智能体路线：会议纪要助手

[课程首页](README.md) · [先选构建器](00-start.md) · [下一步：可复用技能](10-skill.md)

本课做一个按固定格式整理文字的助手，不挂连接器，不申请 API Key。流程依据官方知识库改编；本次未实际创建或进行真机验收。

## 第一步：描述处理规则

登录官方 Step Studio，选择「智能体构建器」。描述输入、输出格式和遇到缺失信息的处理方式。

```text
做一个会议纪要助手。我输入会议文字，你输出：一句话结论、待办表（事项、责任人、截止时间）、待确认问题。
原文没有说的责任人和时间写“待确认”，不能猜测。讨论或建议不能写成已经批准的决定。
仅整理输入文本，不调用外部服务、不发送消息，不增加连接器。
```

## 第二步：检查配置

检查名称、简介、头像与系统指令。名称可用“纪要练习”，简介说明整理范围。先选当前可用默认模型，之后再比较效果；不用为这课另外申请 DeepSeek Key。

将上方的缺失信息规则保留在系统指令中，而不只发送一次普通聊天消息。知识库说明系统指令可编辑，连接器与技能可按需要挂载；这次两者都留空。

## 第三步：用虚构会议测试

输入：

```text
周一练习会议：大家决定先做两页演示。小林负责首页，周五前交付。
有人建议再加排行榜，但还没决定。详情页由谁负责和何时完成还没确定。
```

| 检查点 | 应有结果 |
| --- | --- |
| 已确定事项 | 两页演示；首页责任人为小林、时间为周五 |
| 未定事项 | 详情页责任人与时间列为待确认 |
| 建议与决定 | 排行榜不能写成已决定开发 |
| 只有一句“今天开会了” | 不编造结论和任务，说明信息不足 |

结果不对，查看调试信息，再改系统指令并重测同一段文本。原文说明只能与最新版本对话，历史版本用于查看；不要用旧聊天表现判断修改后的规则。

## 第四步：按智能体入口做手机测试

知识库给出的路线是：网页「真机测试」→ 将测试版本推送到 StepX 手机 → 扫码 → Amoo 空间 → 设置 → 我的作品 → 智能体 Tab → 安装，再从 Agent 列表切换对话。这是原文入口，若当前手机界面不同，按实际页面查找并记录差异。

该智能体与手机 Amoo 主 Agent 相互独立。用同一段虚构会议再次检查；仅网页预览完成时，不写成手机测试通过。

## 最后：先保留测试版

完成条件是正常输入与信息不足两组结果符合规则，并记录网页和手机分别是否通过。公开分发前看[第 07 课](07-release.md)：原知识库中智能体发布与上架为同一动作，需相应校验与审核；这课不要求上架。
