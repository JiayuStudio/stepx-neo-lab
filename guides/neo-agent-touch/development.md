# Neo Agent Touch：从目标到可验证的手机操作

本手册配合 180 秒开发实录阅读。当前应用为 0.1.10 开发版，公开素材工程为 1.0.1，执行客户端 Codex。素材来自真实 Android 应用录屏与本地绘制的讲解动画，公开素材已遮盖位置与 WPS 头像；影片与手册通过研究所公开；应用另提供 0.1.11-beta.1 内测 APK，基于影片所用 0.1.10 增加自选已安装应用、搜索、分类与同类常用，并整理发布构建；新增功能有独立隔离检查，不能据此扩大真实业务已验范围。

## 手机内的运行链

用户对话与限定偏好 → 目标规划 → 应用与数据接收范围 → 本机 MCP / Skills → 视觉观察 → 候选动作 → 原生校验与执行 → 再次观察、读回与结果验证。

控制循环在 Android 应用内运行。无障碍服务取得当前窗口和控件语义，通过系统原生接口执行触控、输入、返回等动作。模型推理通过用户配置的 API 完成，因此这不是完全离线的端侧模型。开发电脑用于构建、安装、被动采集和核验，没有替手机执行影片中的第三方应用点击。

当前 MCP 是进程内 JSON-RPC 适配层：初始化、工具发现、工具调用与技能资源读取经同一原生执行入口处理。它不等于已经开放给外部 Agent 的网络 MCP 服务。官方 Amoo / Step AOS 系统网关、Laya 或其他候选决策模型都不作为已接入能力宣传。

## 为什么既看图，又要系统语义

每轮提供原始截图和同坐标的编号截图。模型先看见目标，再用当前编号定位；系统控件补充边界、类型、可编辑性、选中状态及用途。没有提供用途的控件保留未知，不凭编号杜撰功能。

执行前再次核对窗口、控件身份、版本与控制权。旧截图对应的坐标不会因为模型已经返回答案就继续执行。输入法和其他窗口遮挡时也要重新观察。画面发生变化、目标被遮挡等失败信息返回下一轮，帮助换入口或重新规划。

## “模拟手指”的实际实现

这里实现的是小范围触点变化，不是反检测承诺：

1. 先从当前有效控件取得可见边界，收缩到安全点击区域。
2. 在锚点附近小半径内选择整数触点，不能越过目标边界。
3. 本任务内记录已用触点，不重复使用同一精确位置，也避开精确锚点。
4. 接管后恢复时保留这份记录；新任务重新开始。
5. 安全区域没有新落点时不扩大点击范围。

影片中的圆环仅用于解释触点变化；当前软件按要求仅保留边缘动效。未宣称能隐藏无障碍服务、绕过验证或规避平台识别。

## 文档能力怎样验收

WPS 并不是由开发电脑先写好合同再粘贴。目标消息只有要求、文件命名与修改条件，正文由手机中的模型生成。

本轮真实录制任务的报告为：18 次模型调用、20 个执行动作，两次写入与两次重新打开读回，最终原生正文一致性与目标条款检查通过。另一个保存文件样例的 DOCX 正文解码确认含“每月5日前”，原“每月10日前”不存在。文件样例与最新录制任务是两次不同的回归，不混称同一份文件。

重要的次序是：新建 → 写入并完整核对 → 保存 → 从文件列表重新打开 → 局部替换 → 再保存 → 再打开读回。没有重新打开时，修改工具会返回阶段错误。不能把按钮已点击、输入已发生或模型说完成，等同于文件已经保存正确。

仍需加强的部分包括：对“其他段落保持不变”的独立差异验证、读回不一致后的证明失效处理，以及云端文件状态核验。它们没有被包装成已经修复。

## 接管、故障与状态

控制胶囊默认靠右侧中部，可拖动避免遮挡。用户接管会撤销当前控制权，旧模型回复不能继续操作。交还后先获取新画面。屏幕边缘使用圆角路径、缓存光晕与 GPU 渐变流动，避免在中央盖住内容。

开发中曾出现用返回键收键盘而退出应用的问题，后来改为有超时的键盘显示模式租约，并在执行、结束或接管后恢复先前模式。重复拒绝候选按当前场景、控件和参数记录，避免同一画面连续派发同一失败动作。这份失败记忆当前是运行期机制，不宣称跨进程长期保留。

本轮复杂购物还发现预览任务只有 24 步，而其他复杂流程有 40 步的不一致，已统一预览任务的有限步数上限；十分钟总上限仍然保留。增加步数并不能替代正确定位，因此完整购物成功率仍需继续实测。

## 记忆为什么要克制

当前仅覆盖咖啡与饮食的 8 类限定偏好。从用户自己的对话提取，保存在本机加密存储。明确表达的习惯可以直接记录；推测需要 30 天内至少 3 个不同日期的重复线索，并显示为推测。一次性的要求不覆盖明确习惯，当前指令始终优先。

关闭后不学习、不注入偏好；清空时记录遗忘边界，避免旧历史立即重新生成相同偏好。影片里的少冰、无糖、大杯等属于隔离测试资料，不是用户的真实习惯。跨日实际使用与真实餐饮下单仍需长期验收。

## 适合社区复现的下一步

先从无交易的目标开始，固定应用版本与测试资料，保存动作前后画面和真正的成功证据。分别记录“模型候选”“原生派发”“应用结果”，把失败样例保留在私有测试资料中。文档用新文件和占位符，交易先区分商品规格页、订单核对页、已创建订单和支付成功回执。

外部网络 MCP、正式购物与电影票的成交闭环、关注 / 加购回执、多应用整批目标、真实跨日记忆与长期稳定性，都是后续独立验收项。影片不能替代这些验收。

配乐为 Suno v6 生成的《Touch to Tomorrow — Full Journey》。采用一首完整器乐曲，保留整体结构，以轻微速度调整适配三分钟，没有逐场景切歌或乐段循环。最终声音是否合适仍以实际播放听感为准。
