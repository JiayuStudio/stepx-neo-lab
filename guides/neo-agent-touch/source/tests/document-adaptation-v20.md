# WPS 通用文档适配修订

> 修订阶段记录：下文保留当时的问题与待验状态；本页末尾补记后续复测。当前正式版本与完整验收以 [README](../README.md) 和 [acceptance-v20.json](acceptance-v20.json) 为准。

2026-10-24 · 0.1.20-beta.1，尚待修订后的真实 WPS 复测。

## 已确定的问题

- 首轮目标是新建指定名称的文档，由 Agent 写三段手机内 Agent 工作原理并保存。私有录屏能看到新建、三段正文和正确的保存名称；报告显示一次 document_write，正文状态为 mismatch，保存被拒绝。
- 旧 DocumentReadback 除全文一致外，还无条件要求租赁合同关键词。因此任何通用介绍正文都无法通过。现有证据没有保留原生 SurroundingText 全文，不能断言本次 mismatch 只有这个原因，更不能据此认定已通过全文核验。
- 文件命名只接受同时包含“测试”和“租赁合同”的旧样例名称，与本次原请求不符。

## 修订边界

- 原生全文的偏移、精确比较、后缀矛盾、不可读和部分读回检查保留；只有原请求为租赁合同时才要求合同结构。全文相同但合同结构不足单独标记 content_incomplete；正文不同仍是 mismatch。
- 保存名绑定到原请求明确名称；未指定时使用本轮随机标识生成安全名。首次保存必须在当前原生文件名输入框核对，不以之前的输入回执代替当前名称。
- 本地检测到同名冲突后，清除该尝试名的已保存、重开和恢复资格，拒绝覆盖确认；只允许取消后按带本轮标识的新名保存。不能将同名旧文件作为本次文件重开。
- 保留本轮新建门槛、首次正文空白检查、只允许一次不确定写入、替换前完整读回和全文选中、保存后准确重开，以及 finish 时重新读回。
- 未新增自动重复写入、覆盖正文、打开已有文档或把模型声明当作成功的分支。

## 验证

- DocumentNameRulesTest：47 项纯规则检查通过。
- DocumentReadbackTest：23 项纯规则检查通过，含通用正文和原请求为租赁合同的区别、实际正文变更、追加、部分读回和不可读。
- DocumentRuntime 与 DocumentEvidenceContracts 在独立临时目录完成 Android 编译检查；未构建或安装 APK。
- 扩展的 Android 合成契约尚待根 Agent 在真机执行；实际 WPS 新建、保存和精确重开读回仍待验。合成契约不能替代第三方 WPS 实测。


## 后续真机复测（最终验收补记）

上述“尚待复测”“未构建或安装”描述的是修订时点，后续已完成同源构建与手机内复测。WPS 由 Agent 自行生成三段正文，仅写入一次，保存本轮新文档，重新打开并完整读回；原生正文精确一致，内置阶段验证为 true，独立画面核对通过。该项绑定的正式测试构建摘要为 `3d3307f3f6adc47d0adcaa2c190cd2e1bcde5dad874b0963473adeaab6426e64`。

这只验收新建文档的生成、保存和重开读回；原有文件修改、租赁合同内容、同名冲突实际分支仍待验。首轮 mismatch 与保存被拒绝的失败记录保留，不从后续成功推断其全部成因。最终规则检查为 56 套；分批构建与最后正式包摘要见机器可读验收，未声称全部应用在最后二进制上重跑。
