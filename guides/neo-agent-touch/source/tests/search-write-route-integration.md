# 搜索输入双通道适配

> 修订阶段记录：下文的“未交付”与 55 套检查是实现时点状态，保留用于理解调试过程。后续真机结果补记于本页末尾；当前结论以 [README](../README.md) 和 [acceptance-v20.json](acceptance-v20.json) 为准。

2026-10-24 · 0.1.20-beta.1，未交付修订。

## 观察到的问题

B站搜索输入框有稳定系统编号并已聚焦，Android 输入连接可以完整读回；无障碍节点有文字但没有有效的完整选择范围。因此原先的汇总能力 `can_write=true` 与带编号输入动作不一致：模型给出 `type(id=输入框编号)` 后，旧路由只尝试需要节点完整读回的端口，实际没有填写。

## 调整

- 输入能力分别说明节点、系统输入连接、带编号输入是否可用；节点标注给出实际写入路径。不能读回的节点不再宣称其带编号搜索提交路径可用。
- 带编号输入先确认编号就是该次快照中唯一聚焦的搜索节点，刷新并核验原生节点身份、应用、窗口、位置、编辑状态、节点会话和 EditorInfo。
- 节点可完整读回时仍使用原节点路径；节点不可读而其绑定的系统输入连接可完整读回时，才使用系统路径。没有可核验通道时拒绝，两个完整读回相互矛盾时拒绝。
- 系统路径的每次读回、全选、最终写入都会重复核对同一节点与编辑器会话；实际派发前还必须匹配最后一次样本。在同一应用中更换输入框、窗口或会话不能借用原编号。
- 两条路径复用同一待核验输入和提交记录。已派发但未确认的输入不能通过更换路径再次派发；真正的新写入才开启新的搜索提交周期。
- 该改动不扩大 `ACTION_IME_ENTER` 支持，不会启用专用输入法，不把输入或提交回执当成搜索成功。

## 验证边界

`SearchWriteRouteRulesTest` 的 51 项纯规则检查通过，覆盖错误编号、绑定丢失、不完整读回、两端冲突、跨路径待核验输入、A→B→A 新写入、实际写入登记、派发后异常和失效租约。已与文档命名规则测试一并接入单元入口，本次共 55 套规则通过。

真实 B站搜索与其他应用回归由独占手机的测试流程另行验证。此记录只证明规则与路由修订通过本地检查，不宣称真机搜索已经完成。


## 后续真机复测（最终验收补记）

后续同源手机内复测已观察到 B站正确填词、提交搜索并打开视频动态播放，淘宝和百度网盘也分别完成搜索并显示目标范围结果。B站实际选中第二条，因此严格“第一条”目标仍为部分通过；搜索路由修复不能替代列表顺序选择验收。B站、淘宝和网盘这批绑定的正式测试构建摘要为 `3d3307f3f6adc47d0adcaa2c190cd2e1bcde5dad874b0963473adeaab6426e64`。

最终规则检查为 56 套。隔离自有编辑器的 ACTION_IME_ENTER 合成契约仍保留失败：系统接收返回 true，但未获得 SEARCH 回调；不能用这些业务结果把该契约改记为通过。原始失败、业务结果和最后正式包安装证据分别记录于机器可读验收；未声称所有应用、所有输入通道或最后二进制上的全部应用复测通过。
