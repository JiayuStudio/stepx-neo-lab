## 一句话结论

Amoo 是 StepOS 系统级 AI 助手：能用「说话」完成大量**手机系统级操作**（开 App、改设置、打电话发短信、日历待办、相册等）。  
**打开 App 这类原子能力本轮已实测可用**；**在第三方 App 界面里连续点按、搜索、点赞等 GUI 操作，固件里有相关代码与文档，但原稿所述测试未触发**——Amoo 自己也会明确说「界面内的连续点按操作不支持」。

> 证据等级说明（全文通用）：  
> **运行证实** = 本轮在真机上看到调用与结果；**静态存在** = 固件包/技能文档里有，但本轮未触发；**文档声明** = 固件内置类目文档写了 method；**历史资料** = 2026-10-17/18 的其他口径清单，**不是**本轮实时支持表，数字不可混用。

## 1. Amoo 是什么？和「阶跃AI App」有什么区别？

| 入口 | 是什么 | 本轮角色 |
|------|--------|----------|
| **Amoo 对话** | 系统 AI 桌面 / 助手（包名 `com.stepos.ailauncher`） | 主入口；说话 → 调度手机原子能力 |
| **阶跃AI / 跃问 App** | 独立 App，包名 **`cn.yuewen.ywapp`**（**不是**「阅文」阅读 App） | 其内可部署 **StepClaw** 对话；本轮第三次实测走这里 |
| **StepClaw** | 端侧 OpenClaw 网关相关（包名 `com.stepos.stepclaw`） | 可在阶跃AI App 内对话；也可作为节点执行 `ability.call` |

简单记：**想控制手机系统能力，优先用 Amoo**；阶跃AI App 里的 StepClaw 是另一条对话入口，本轮在那里点名要 `gui_agent` 时，实际走了网页浏览器工具，**没有**在手机上操作 B 站界面。

## 2. 它怎么做到的？（生活化原理）

可以把流程想成「你说话 → 手机先听懂一点 → 云端管家派活 → 活又回到你手机上执行」：

```
你说话
  → 端侧小模型 stepos-sla 先理解意图（本机，约 100–185ms，运行证实）
  → 云端 Claw（OpenClaw）决定调用哪个能力
  → 通过云端中继回到手机本地节点（本轮日志节点名 NODE_ID）
  → 用 MCP 协议调用系统原子能力包（com.stepos.common.ability.proxy）
  → 手机真正执行：例如 open_app_by_name 打开某个 App
```

- **MCP**（Model Context Protocol）：工具调用的「插头标准」，让云端管家能安全调用手机上的能力。  
- **原子能力**：一件件明确的系统动作（开 Wi‑Fi、打开某 App、发短信……），不是「像人一样在屏幕上乱点」。  
- **GUI 自动化 / gui_agent**：文档里写的是「在第三方 App 里按任务描述自动点按」。固件里有文档、代码和特权权限（**静态存在**），但本轮两个入口都**没有真正跑起来**（**运行证实：未触发**）。

## 3. 这次测了什么？结论是什么？

本轮条件：未 ROOT、未装 APK、未改权限；仅 USB ADB 只读观察 + 对话实测（详见专业版复现说明）。

### 三次实测（摘要）

1. **Amoo：「在阅文 App 里搜索三体…」**  
   - 链路：Amoo → 云端 Claw `ability.call` → 本地节点 → MCP 调 `open_app_by_name`。  
   - 两次因名称「阅文」失败（错误码 10001「目标APP不存在: 阅文」）。  
   - 随后 `common_ability_get_app_list`，再 `open_app_by_name` 打开了 **`cn.yuewen.ywapp`（阶跃AI/跃问）**——测试者曾把该包名误当成阅文。  
   - 任务标记 COMPLETED；`isGuiAgent=false`；**App 内无搜索操作**。  
   - **运行证实：** `open_app_by_name`、`common_ability_get_app_list`。

2. **Amoo：「打开B站，搜索三体，只看搜索结果列表，不要点开视频…」**  
   - 只调用了 `open_app_by_name` 打开 `tv.danmaku.bili`。  
   - Amoo 原话要点：「B站已经打开了，但搜索这一步我执行不了……我也无法在它的界面里替你点搜索框……这类界面内的连续点按操作不支持」。  
   - 截图证据：`pack/s4s.png`。  
   - **运行证实：** 打开 App 可用；App 内点按当前不可用（助手自述 + 日志无 gui 执行）。

3. **阶跃AI App 内 StepClaw：「用 gui_agent 在 B 站里搜索三体…」**  
   - 工具卡片显示 **browser×5 + read×1**，**未出现 gui_agent**。  
   - 返回了网页侧的 B 站搜索结果列表；手机前台约 3 分钟始终在阶跃AI，**从未切到 B 站**；本机日志无本地节点 GUI 调用。  
   - 截图证据：`pack/s11s.png`。  
   - **运行证实：** 该入口用云端/桌面浏览器完成搜索摘要，**不是**手机 GUI。


> 原稿引用的两张界面截图未随本文提供；此处保留文字描述。

### 总结论

| 能力类型 | 状态 | 证据 |
|----------|------|------|
| 打开 App、查已装应用列表等原子能力 | **可用** | 本轮运行证实 |
| 系统设置 / 电话短信 / 日历等（文档中的大量 method） | **文档声明存在**；本轮未逐条复测 | 固件 `android-abilities` 13 类目文档 |
| App 内连续点按（gui_agent） | **固件内置，但原稿所述测试未触发**（或灰度/开关关闭；原因**未验证**） | 代码+文档静态存在；两入口均未触发；Amoo 自述不支持 |
| 支付宝 A2A | 代码存在，限支付宝场景 | 静态存在；本轮**未运行验证** |

历史资料（2026-10-17 能力清单 PDF、2026-10-18 Excel「104 项方法 / 29 应用」、HTML「69 应用粗分类」等）口径不同，**不能与本轮数字相加或当作实时支持率**。

## 4. 完整上手教程（一步步）

### 4.1 打开 Amoo

1. 在 StepX Neo 上从 AI 桌面 / 助手入口进入 **Amoo 对话**（`ChatMainActivity`，action `com.stepos.ailauncher.action.OPEN_CHAT`）。  
2. 确认能看到聊天输入框（可文字或按住说话）。  
3. （可选）若你使用的是 **阶跃AI App 内的 StepClaw**，请意识到那是**另一入口**，路由行为可能不同（本轮已证明：点名 gui_agent 仍可能走 browser）。

### 4.2 怎样说话最有效

- **一件事说清楚**：要什么 App、做什么、**不要做什么**。  
- **优先说系统能力**：亮度、Wi‑Fi、打开某某 App、加日程、发短信……  
- **避免「打开 XX 再搜 / 点赞 / 下单」类连环界面操作**——当前会停在「只打开」或改走网页搜索。  
- **App 名称用手机桌面上显示的名字**（「哔哩哔哩」或「B站」以你机上显示为准）；不要用猜的品牌别名硬套（本轮「阅文」失败即一例）。

### 4.3 建议的第一次练习（约 3 分钟）

1. 说：「打开计算器。」→ 应看到计算器被拉起（历史资料亦有类似原生验证；本轮对 B 站/阶跃AI 打开为运行证实）。  
2. 说：「打开蓝牙设置。」或「把媒体音量调到 30%。」→ 系统设置类（文档声明；本轮未逐条复测）。  
3. 说：「打开 B 站，并在里面搜索三体。」→ **预期：只会打开 B 站，搜索步骤失败或助手说明不支持点按**（本轮运行证实）。

### 4.4 如何确认它真的做了

- 看手机界面是否真的跳到目标 App / 设置页。  
- 看 Amoo 是否标记「已完成」，并阅读它有没有说「搜索这一步执行不了」。  
- 不要只听「已完成」四个字——本轮打开 App 后任务也会 COMPLETED，但 App 内并未操作。

## 6. 固件里写了哪些能力类目？（13 类 · 文档声明）

以下类目来自固件内置技能包 `android-abilities`（StepClaw assets），是**路由与 method 说明书**，不等于本轮逐条实测通过：

| # | 类目 ID | 中文 | 典型能做什么（摘自文档描述） |
|---|---------|------|------------------------------|
| 1 | phone_comm | 电话与短信 | 拨打/接听、短信收发查询、通话记录、话费流量等 |
| 2 | contacts | 联系人与黑名单 | 通讯录增删改查、黑名单 |
| 3 | system_settings | 系统设置 | Wi‑Fi/蓝牙/亮度/音量/深色模式/截屏录屏等 |
| 4 | media_gallery | 相册与媒体 | 搜图、滤镜裁剪、视频剪辑任务、高光等 |
| 5 | map_navigation | 地图导航天气 | 定位、天气；地图多为云侧 |
| 6 | app_device | 应用与设备 | **仅**打开 App、日历、音乐小组件、计算器、录音机等；App 内操作文档要求改走 gui_agent |
| 7 | web_search | 网络搜索 | 网页搜索、热榜、抓取（云侧） |
| 8 | file_memory | 笔记·文件·记忆 | 笔记/待办、文件列表与安全删除等 |
| 9 | gui_agent | GUI 自动化 | 第三方 App 内搜索/下单/点赞等 —— **本轮未对用户开放** |
| 10 | scheduled_tasks | 定时任务与时钟 | cron（云侧）、闹钟、倒计时 |
| 11 | session_runtime | 会话与运行时 | 会话管理、exec/bash（云侧）、TTS 音色（端侧） |
| 12 | log_report | 设备日志 | 开始/停止录日志（诊断用） |
| 13 | （路由总册） | SKILL.md | 类目路由器：第三方 App 内操作优先读 `gui_agent.md` |

方法名数量（仅统计各类目 `.md` 中显式 `method="..."` / 文档列出的工具名，**文档声明**）：系统设置约 121、电话短信约 80、相册约 51、应用设备约 40、文件记忆约 31、联系人约 22、地图约 18、定时约 14、会话约 12、搜索约 6、日志 2、gui_agent 1。**这些数字不是「实时可用数」**。

## 7. 怎么用最有效？（实用建议）

1. **把 Amoo 当「系统遥控」**，不要当「会替你刷短视频的手指」。  
2. **任务拆开**：先「打开 App」，再自己点；或改用「网页搜索公开信息」。  
3. **约束写清楚**：「不要下单」「不要发送」「只要列表」——对日历/短信等原子能力仍然有用；对 GUI 目前帮不上忙，因为 GUI 根本没跑起来。  
4. **名称要对**：用桌面显示名；失败时可让它「列出已安装应用再打开」。  
5. **区分入口**：系统能力用 Amoo；在阶跃AI·StepClaw 里看到 browser 卡片，说明结果可能来自网页而非手机界面。  
6. **敏感操作**：删除、群发、支付类——文档与历史清单均提示需确认；本轮未测支付。

## 8. 常见问题

**Q1：为什么说「已完成」但 App 里什么都没搜？**  
A：本轮日志显示任务在「打开 App」后即 COMPLETED，且 `isGuiAgent=false`。完成的是打开动作，不是你以为的全程。

**Q2：固件里不是有 gui_agent 吗？**  
A：有文档、有相关代码与系统特权（静态存在）。但本轮 Amoo 与 StepClaw 均未触发；Amoo 明确说不支持界面内连续点按。是否灰度/账号开关导致——**未验证，不下结论**。

**Q3：阶跃AI App 搜出了 B 站结果，算不算 GUI 成功？**  
A：不算。工具是 browser×5+read×1，前台未切到 B 站，是网页侧结果（运行证实）。

**Q4：`cn.yuewen.ywapp` 是阅文吗？**  
A：**不是。** 本轮核实为 **阶跃AI / 跃问** App。

**Q5：历史 PDF/Excel 里写微信能发消息、有 104 项方法，为什么这里不保证？**  
A：那是 **2026-10-17/18 历史口径**（能力清单 v4、Excel 检索回执、HTML 69 应用粗分），与固件 13 类目文档、与本轮实测是**三套材料**。综合速查也写明：69、29、104 **不能混用**。

**Q6：完全断网还能用吗？**  
A：端侧小模型推理在本机；但本轮主链路含「云端 Claw 中继」。历史晚间报告记载真实断网时部分请求未发出。**离线可用性未在本轮验证。**

**Q7：无障碍服务是关的，GUI 还能做吗？**  
A：原稿记录了无障碍服务状态。固件给 ability/stepclaw 等系统共享 UID 授予了 `INJECT_EVENTS`、`READ_FRAME_BUFFER` 等特权，文档结论是 GUI 执行**可不依赖**无障碍服务——但因 GUI 未触发，**是否真能在关闭无障碍时跑通，未验证**。

**Q8：我想自己查 gui_agent 有没有注册怎么办？**  
A：专业版写了只读思路：经 StepClaw 对节点执行 `ability.list`，query 描述「在第三方 App 内操作」。本轮**未执行**该查询；历史资料（2026-10-18）曾记录精确查询返回空结果——仍属历史口径。
