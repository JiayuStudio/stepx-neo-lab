# DeepSeek API Key：申请、配置与第一次使用

[研究所首页](../../README.md) · [新手课程](../../sections/start-here.md) · [自研 Studio 指南](../neo-studio/README.md)

本课由 JIAYU STUDIO 编写，适合第一次配置 AI 接口的读者。完成后，你应能申请自己的 DeepSeek API Key，在支持的工具中保存配置，并用一次短对话判断是否接通。

**适用范围**：DeepSeek 官方 API、支持 Chat Completions 的客户端，以及研究所自研 **StepX Neo Studio 1.2.3**。官方 **Step Studio 网页**使用其自身提供的云端模型；这里的配置不会替换网页后端模型，也不是第一款官方 Studio 应用的必修前提。

核对日期：2026-10-20。官方模型与页面可能更新，文末保留查询入口。

## 1 · 先认识三个东西

| 名称 | 你需要理解的内容 |
| --- | --- |
| API Key | 让软件代表你的账户调用接口的密钥；不是登录密码，也不是模型名称 |
| Base URL | 接口服务地址，告诉软件向哪里发送请求 |
| 模型 ID | 实际调用的模型标识，需要按官方文档或模型列表填写 |

在 DeepSeek 网页聊天与使用 API 是两条使用路径。API 调用按开放平台规则计费；能登录聊天网页，不代表 API 已有可用余额。请先查看[当前定价](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)与平台余额，不把免费聊天理解为免费 API。

## 2 · 到官方平台申请 Key

1. 打开 [DeepSeek 开放平台](https://platform.deepseek.com/)，按页面提供的方式注册或登录。已有登录状态可以直接进入下一步。
2. 左侧进入 **API keys**，也可打开 [API keys 页面](https://platform.deepseek.com/api_keys)。
3. 点击 **创建 API key**。
4. 在名称框填写用途，例如 `Neo 学习练习`，方便日后识别；名称不用填写真实姓名。
5. 点击弹窗的 **创建**。平台说明完整密钥只在创建时可见、可复制；立即保存到你自己的密码管理器，再填入要使用的软件。
6. 到左侧 **用量信息**查看账户状态；需要付费额度时，自己进入 **充值**，核对金额与支付信息后决定是否充值。

忘记保存后，不要试图从遮罩字符串恢复密钥；重新创建并更新客户端，确认新配置能用后再停用不需要的旧 Key。不要将完整 Key 发进群聊、截图、GitHub、应用前端或公开 APK；教学中只使用文字占位符。

> 本教程核对了 API keys 页面、创建弹窗和名称字段，没有代你创建新 Key、充值或读取完整密钥。页面按钮发生变化时，以当前官方平台提示为准。

## 3 · 通用配置：填对这四项

打开你使用的软件的模型或 API 设置，选择自定义服务商或 DeepSeek，按下表填写。

| 配置项 | 填写内容 |
| --- | --- |
| 接口协议 | OpenAI 兼容 / Chat Completions |
| Base URL | `https://api.deepseek.com` |
| API Key | 你刚创建的完整 Key；普通 Key 输入框中不要自行添加 `Bearer ` |
| 模型 ID | 入门先填 `deepseek-flash`，或从服务商实际返回的模型列表选择 |

如果软件明确要求“完整请求 URL”，填写 `https://api.deepseek.com/chat/completions`。不要把聊天网站地址、开放平台管理页或接口文档网址填作 Base URL；不要重复拼接 `/chat/completions`。

截至核对日，官方文档列出的模型包括 `deepseek-flash` 与 `deepseek-v4-pro`。本教程使用前者做最小连通练习，之后再按任务与价格选择。旧教程里的模型名不要直接照抄，先查[官方首次调用说明](https://api-docs.deepseek.com/zh-cn/)。

## 4 · 在 StepX Neo Studio 中配置

以下字段与按钮按研究所自研 **StepX Neo Studio 1.2.3** 源码核对；不是官方 Step Studio 网页的操作步骤。

1. 进入 **模型与 API**，点 **＋ 新配置**。
2. 在 **快速填写服务商**选择 **DeepSeek**，自动填入官方地址、兼容协议与模型名；仍对照上一节检查。
3. 将 **配置名称**设为 `DeepSeek 学习`，在 **API Key**输入自己的完整 Key。
4. 初次连通时，**单次最大输出 token**可先设 `1024`，**推理模式**选 **关闭推理，直接输出**。这是练习配置，不是服务商的固定上限。
5. 点 **保存配置**。需要查询可用模型时，点 **保存并检测模型**，选择返回的模型后再次保存。检测失败不一定代表对话接口不可用，可按官方当前模型 ID 手动填写后测试。
6. 点 **保存并测试**。这会真的发起一次短 API 请求，可能计费；只按一次，等待结果。
7. 返回 **AI 助手**，选中刚保存的配置，新建不关联项目的对话，发送下方练习。

```text
请用三句中文解释：什么是 API、什么是 API Key、什么是模型 ID。
只作概念说明，不创建或修改项目。
```

成功标准：收到有内容的回答，并能在工具的用量记录或开放平台用量中检查此次调用。只有“保存成功”或“检出模型”还不能证明生成请求成功；平台用量显示也可能存在延迟。

编辑已有配置时，1.2.3 的 Key 框留空会保留旧密钥；更换为新 Key 时粘贴完整新值并保存。这里支持 Chat Completions；不要把配置切成 Responses 协议。有关模型设置范围见[自研 Studio 指南](../neo-studio/README.md)。

## 5 · 想把 AI 放进自己开发的应用？

先完成上面的独立对话，再考虑应用集成。**给你自己的开发工具配置 Key**，与**把开发者 Key 写进面向用户发布的 App**是两件事。

准备公开应用时，让后端保存开发者 Key，由应用调用你自己的后端；为调用增加用户认证、额度和速率限制。不要把开发者 Key 放进网页 JavaScript、公开源码或安装包。供使用者自填 Key 的工具，也应明确调用哪个服务商、如何保存与删除密钥。

可用下面的需求提示词开始设计，内容不包含真实 Key：

```text
为一个学习问答应用设计 DeepSeek 接入方案。
前端只向自己的后端发送问题，DeepSeek Key 通过后端的秘密配置读取。
先列出登录校验、每用户额度、限流、超时与错误提示，再实现最小接口。
说明我需要在部署平台手动填写哪些配置，不要求我把 Key 发进对话。
先用模拟返回检查界面；真实接口成功与模拟成功分别记录。
```

这段是开发思路示例，并不表示官方 Step Studio 当前已提供任意后端密钥配置入口。若所用构建器没有明确支持的秘密配置能力，先确认其文档，不把 Key 当作提示词交给它。

## 6 · 出错时按这里排查

| 表现 | 先做什么 |
| --- | --- |
| `401` | 核对完整 Key 是否复制正确、是否已停用；确认请求发往官方 API 域名 |
| `402` | 检查开放平台余额；是否充值由自己决定，创建更多 Key 不能补充余额 |
| `400` / `422` | 阅读具体参数错误；检查模型名、请求格式、输出限制和客户端协议 |
| `429` | 降低请求频率与并发，等待后再试，不连续点击测试 |
| `500` / `503` | 稍后重试，必要时查看官方服务状态 |
| 模型找不到 | 查询当前官方文档或检测模型列表，不凭展示名称猜模型 ID |
| 检测成功但聊天失败 | 模型列表与生成是不同请求；继续核对余额、模型和生成参数 |
| 超时或网络错误 | 检查网络与接口地址，保留错误码；不要因超时反复提交相同长任务 |

错误码含义依据 [DeepSeek 官方错误码](https://api-docs.deepseek.com/zh-cn/quick_start/error_codes/)。每次真实生成都可能产生费用，重试前先确认上一条是否已完成。

## 7 · 完成这一课后

- 能在自己的账户创建并保存 Key。
- 能区分 Base URL、完整请求地址和模型 ID。
- 能完成一次短回答，并找到对应的用量记录。
- 知道如何更换或停用 Key，以及不再使用时关闭哪些客户端配置。
