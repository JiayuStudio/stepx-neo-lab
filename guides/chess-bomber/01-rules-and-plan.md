# 1. 先写规则，再让 Studio 开发

[返回教程](README.md) · [下一章](02-studio-workflow.md)

## 把玩法说清楚

核心循环是：帅、将亲自走格 → 选择棋子炸弹 → 落子 → 三秒后按对应棋子的走法引爆 → 躲开危险或击败对方。角色移动、炸弹库存和爆炸判定是三套概念，不应让AI把它们混成传统轮流走棋。

先做一个二维灰盒：棋盘、两名角色、一个炸弹、一个障碍即可。确认移动、落子、爆炸和胜负成立，再加入六种棋子、联机、美术和音频。已有项目局部修复时，只回归受影响环节，不必每次重做整个原型。

## 当前规则表

棋盘为9列、10行交叉点，以左上角为 `(0,0)`。红方出生于 `(4,9)`，黑方出生于 `(4,0)`。炸弹自身所在格也属于爆炸范围。

| 棋子 | 范围 | 阻挡规则 |
| --- | --- | --- |
| 仕 | 四个斜向相邻格 | 障碍格不受击 |
| 相 | 四个田字对角点 | 象眼有障碍或炸弹，该方向被封住 |
| 马 | 日字八个目标点 | 马腿有障碍或炸弹，该方向被封住 |
| 车 | 四个正交方向延伸至边界 | 第一格障碍前停止；遇其他炸弹触发连锁并停止 |
| 炮 | 四个正交方向各最多五格 | 每方向可穿一格障碍，第二格停止；遇其他炸弹连锁并停止 |
| 兵/卒 | 向前一格；过河后加左右相邻格 | 不攻击障碍格 |

**只有炮有穿一格障碍的规则。** 马、相按自身路径判断阻挡，不能用“所有特殊棋子都忽略障碍”的捷径。障碍本身不可站人、不可放弹，也不绘制火焰。

每方同类炸弹同时在场上限：仕、相、马、车、炮各2枚，兵5枚。炸弹消失后库存恢复；不要误做成整局只能用这些次数。

每局开始前倒数3、2、1，期间双方和AI均不能行动。正式开打后才计算120秒；超时为平局，不加分也不扣分。

## 地图必须用坐标表达

“在这里加障碍”需要先把截图位置转换为明确格点。本案例的最终默认地图为：

```text
(1,2) (4,2) (7,2)
      (3,4)
             (5,5)
(1,7) (4,7) (7,7)
```

其中 `(4,2)`、`(4,7)` 是后续根据截图新增的两个中路格，不是一整排墙。两端出生点仍有出口，82个非障碍格全部连通。

每次改地图，检查三件事：角色能否离开出生点；双方能否互相到达；旧回放是否仍使用旧地图。不能为了当前版本方便，直接把所有历史回放画成新地图。

## 分工与阶段产物

| 阶段 | 交给 Studio | 独立操作与验收 |
| --- | --- | --- |
| 最小原型 | 游戏状态、移动、一个炸弹、结束条件 | 实际进入并玩完一局 |
| 规则扩展 | 六种爆炸、阻挡、连锁、AI危险判断 | 用固定场景逐格对照 |
| 移动端 | 横竖布局、安全区、多点触控 | 浏览器多尺寸和实体手机 |
| 服务功能 | 账号、UID、对局、大厅、排行、回放 | 新建/恢复账户、重新开局、刷新、重放 |
| 音乐与宣传 | 曲库、静音、结果音效、演示模式 | 音乐生成与处理、真实录制、成片检查 |

不要把“Studio说完成”当作独立测试证据。它的构建与测试报告有价值，但还需要另一个实际入口验证最终产物。
