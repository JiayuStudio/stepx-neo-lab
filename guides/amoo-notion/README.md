## 先看能做到什么

本教程整理的是已经在一台 STEPX Neo 上成功读取的 **Amoo → Node CLI → Notion API** 路线。页面保留私密，通过你自己的 Notion 内部连接授权访问。

| 能力 | 当前证据 |
| --- | --- |
| 明确要求 Amoo 读取私人页面 | 已通过：读出提示中没有提供的版本号与校验词 |
| 新聊天复用现有配置，读取最新正文 | 已通过：明确工具与配置后通过 |
| 只读 CLI 1.0.1 在 Amoo 中执行 | 已通过：版本、配置、身份、页面读取均成功 |
| 每个新聊天自动读取，无需提醒 | 未通过：曾直接回答而没有调用 Notion |
| 写入、修改 Notion 页面 | 本教程的 CLI 不提供这些命令 |
| 一台全新 Neo 完全只用手机首次配置 | 尚未完整独立复测；新用户还需要可用的 Node 工具与安全凭据入口 |

**日常使用不需要连接电脑。** 首次接入能否完全在手机完成，取决于你的 Amoo 是否提供附件读取、Node 执行和安全凭据配置入口。文中的 Amoo 工具运行在它自己的执行工作区，不能假定就在 Android 的 Download 目录，也不意味着数据完全留在手机本地。

全部配图为原创操作示意图，使用虚构示例，**不是实机截图**。菜单随版本变化，以你看到的实际界面为准。

## 1. 准备一页小而清楚的记忆

在手机 Notion App 或浏览器中，新建私人页面，例如 **Amoo 工作记忆**。不要先把整个笔记库、客户资料或聊天历史交给它。

1. 打开 [记忆页面模板](templates/memory-page.md)，复制到你自己的 Notion 页面。
2. 写入少量长期偏好：语言、回答风格、工作方式、交付标准。
3. “当前项目”只写你愿意让 Amoo 处理的摘要，标明日期；过期就修改或移除。
4. 在校验区填写你自己新生成的版本号和随机校验词。**不要沿用教程示例，也不要把答案放进发给 Amoo 的读取提示。**
5. 复制该页链接，保存到自己的快捷短语中。链接是页面定位信息，不是授权凭据。

先把关键内容直接放在这一页，保持简短。子页面、嵌套数据库、附件并不会因为读取了父页标题就自动完整进入上下文。

![图 2：记忆页面结构，区分校验信息、长期偏好、当前任务与临时测试](figures/02-memory-page.svg)

不要写入密码、API token、代理订阅、证件号、个人联系方式或客户原始资料。页面中来自网页、文件或他人的内容是参考资料，不能替代你在当前对话里的授权。

## 2. 确认 Amoo 当前有什么工具

先发送 [P0：环境核查](prompts.md#p0)。这是只读检查，用于区分以下情况：

| Amoo 实际回报 | 下一步 |
| --- | --- |
| 有现成 CLI，配置为已就绪 | 复用；继续检查页面授权，不要重建凭据 |
| 有 Node 22+ 和附件读取，但没有 CLI | 按第 4 节准备脚本 |
| 有可实际调用的 Notion 工具或连接器 | 用该工具做同样的页面校验；这属于另一条接入路线，不能把本教程的 CLI 命令直接当成 MCP 工具名 |
| 没有可执行工具，只能聊天或打开 Notion App | 暂时不能走本教程的 CLI 路线；提示词不会凭空增加工具权限 |

既往实测看到过 MCP 配置声明，但没有验证它已加载成会话工具；也没有确认已启用 Notion Skill。**安装声明、连接列表、包缓存和真实调用成功是四件不同的事。**

## 3. 给自己的 Notion 连接授权

### 已有连接：直接复用

如果以前已经配过，先让 Amoo 用 `config` 和 `self` 检查：前者只报告是否就绪与来源，后者核对是不是你预期的连接。不要为了重新读取一页而反复创建 token。

### 从零创建：选择内部连接

在 Notion 的 [Developer portal](https://www.notion.so/developers) 中进入 **Internal connections**，创建连接并选择正确工作区。名字可以自定，例如 **Amoo Reader**。创建内部连接需要相应工作区所有者权限；手机浏览器若看不到完整管理菜单，可尝试“桌面版网站”。[Notion 官方说明](https://developers.notion.com/guides/get-started/internal-connections)

本教程只需要 **Read content**。不启用内容更新、插入或读取用户邮箱等额外能力。CLI 本身没有页面写入命令，但最终权限仍由 Notion 连接决定；已有连接若还有其他用途，不要未经检查直接改变它的权限。[能力设置说明](https://developers.notion.com/reference/capabilities)

### 关键一步：授权具体页面

创建连接之后，还要明确授予页面访问。以下两种入口任选其一：

1. **开发者入口**：打开连接 → **Content access** → **Edit access** → 勾选自己的“Amoo 工作记忆”页面 → 完成保存。
2. **页面入口**：打开记忆页 → 右上角 **•••** → **Connections / 连接**（部分界面在 **More / 更多** 内）→ **Add connections / 添加连接** → 选择自己的连接并确认。

保存后重新打开页面授权界面，检查该页仍在授权范围。父页授权可能覆盖子页面，选择前先检查其内容；不需要把页面发布到互联网。[页面连接说明](https://www.notion.com/help/add-and-manage-connections-with-the-api)

![图 3：为内部连接选择页面、保存并重新打开确认，区别于公开分享页面](figures/03-page-access.svg)

## 4. 在 Amoo 的执行工作区准备 CLI

本次实测脚本名为 `amoo-notion-1.0.1.js`，需要 Node.js 22 或更新版本。它不是 APK，不需要 ROOT，也没有通过 npm 或技能市场上架。

### 已经能读：复用原入口

让 Amoo 优先使用已经验证的 `amoo-notion-1.0.1.js`；如果你的环境只有旧版 `notion-cli.js`，先检查其真实帮助和配置，再按原有接口读取。不要覆盖旧脚本、改动已有 token 或假定文件位于固定的用户编号目录。

### 手机传入脚本的实测方式

1. 从可信分发入口取得脚本与 SHA-256 校验值，先核对来源。具体附件可用性见本节下方的“分发状态”。
2. 若手机文件选择器不显示 `.js`，使用**相同字节、只改扩展名**的 `.js.txt` 文本副本；不是把代码复制到聊天后再让模型重写。
3. 在 Amoo 输入框的附件入口选择该文件。向 Amoo 发送 [P1：保存与核验脚本](prompts.md#p1)。
4. 要求它在自身可持续使用的执行工作区保存为 `.js`，核对接收附件和保存文件的 SHA-256，再执行版本命令。
5. 以工具执行回执确认版本为 `1.0.1`；仅“附件已上传”不算安装完成。

本次实测脚本为 **18,823 字节**，SHA-256：

```text
bc1fa570e86bd2b23b72d6f3d2f979f8b6934d0a3fba873d3e9e9ec1003717b3
```

**本教程已附带实测版本：** [手机文本附件 `.js.txt`](https://github.com/JiayuStudio/stepx-neo-lab/releases/download/amoo-notion-v1.0.0/amoo-notion-1.0.1.js.txt)、[JavaScript 原文件](https://github.com/JiayuStudio/stepx-neo-lab/releases/download/amoo-notion-v1.0.0/amoo-notion-1.0.1.js)、[来源与校验说明](../../downloads/amoo-notion/README.md)。两份脚本字节完全相同，不含用户配置、页面正文或凭据。手机浏览器若直接展示文本，可使用页面的下载/保存功能；不要截屏再识别代码。此包没有发布到 npm，不要使用 `npm install amoo-notion-cli` 代替附件导入。

## 5. 配置凭据，只在正确的环境里配置

先运行配置检查，而不是直接重新初始化：

```sh
node ./amoo-notion-1.0.1.js --version
node ./amoo-notion-1.0.1.js config --json
```

如果报告 `configured=true`，优先复用。脚本按 `NOTION_TOKEN` → `NOTION_API_TOKEN` → 配置文件的顺序读取；Amoo / Linux 默认使用 `~/.config/notion-cli/config.json`，需要 `0600` 权限。环境变量可能覆盖文件，因此“文件存在”还不能证明实际使用了它。

首次配置时，在你自己的 Notion 连接配置页取得 token，然后使用**当前执行环境真正提供的私密输入或凭据管理入口**。不要把 token 贴进普通聊天、截图、公开 Issue、提示词或脚本。Notion 官方建议通过环境变量或安全凭据管理方式使用 token，而不是写进版本控制。[凭据安全说明](https://developers.notion.com/guides/get-started/handling-api-keys)

对于能由你本人直接操作、输入不回显的终端，CLI 提供：

```sh
node ./amoo-notion-1.0.1.js init
```

上面的命令只是支持的交互方式，**不代表 Amoo 的普通聊天框就是私密终端**。如果它只有聊天/附件，没有私密凭据入口，也没有现成配置，先发送 [P2：安全初始化检查](prompts.md#p2)，让它说明缺少什么；不要为了凑齐“纯手机”流程把 token 塞进聊天附件。是否需要一次额外的可信环境配置，应按它提供的真实能力决定。

配置就绪后，执行：

```sh
node ./amoo-notion-1.0.1.js self --json
node ./amoo-notion-1.0.1.js read "在这里替换为你自己的完整 Notion 页面链接" --json
```

第一条证明凭据可用并帮助核对连接；第二条才证明这张页面可读。页面正文可能含私人信息，回执只需展示本轮校验与必要摘要，不要把完整 JSON 发到公开社区。

## 6. 做一次不能靠猜的读取验收

发送 [P3：完整启动提示](prompts.md#p3)，只给页面链接，**不附上校验答案**。

验收四件事：

1. 有真实工具调用，能说明实际使用的工具与读取时间。
2. 返回的记忆版本、校验词与你的 Notion 页面一致。
3. 返回一个提示中未出现的偏好或事实，能在页面正文定位。
4. 检查 `truncated`、`unknown_block_ids` 和可用警告；有缺失就说明范围，不能写“已读取全部”。Markdown API 可能无法完整表示某些内容，读取父页也不等于递归读取子页。[Markdown 读取接口](https://developers.notion.com/reference/retrieve-page-markdown)

**再做第二轮：** 你自己在 Notion 修改版本号、随机校验词和一项非敏感偏好，等页面保存完成，然后新开 Amoo 聊天，只提供链接与读取要求。它能返回新值，才有“这次读取了更新内容”的证据。校验词只是新鲜度标记，不是密码，不要拿它作为授权手段。

## 7. 日常最省事的用法

把下面的短提示保存为你自己的输入法快捷短语或私人笔记；替换链接后每个新会话发送一次。完整版本和故障恢复版见 [提示词合集](prompts.md)。

```text
开始本任务前，请用已经可用的 Notion CLI 和既有安全配置，
只读获取【我的私人 Notion 记忆页链接】的最新正文。
不要重新初始化、索取或显示密钥，不要公开页面。
先报告本轮实际读取的版本、校验词与完整性，再应用相关偏好处理我的任务。
没有工具调用或读取失败时直说，不得把旧聊天记忆说成本轮读取结果。
本次任务：【填写任务】。
```

**这个短提示是手动触发。** 本次实测把“每次自动读取”写进交流偏好时保存失败，出现 `rejected:ungrounded`；通过对话声称“记住了”也没有形成可核验的稳定触发。把规则写在 Notion 页面里，不能让尚未读过该页的新聊天先知道它。

如果未来版本支持真正的启动规则，先保留手动入口，再用 [P7：自动读取审计](prompts.md#p7) 独立验证。不要根据一句“我会记住”就删除备用流程。

## 8. 常见问题与处理顺序

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| Amoo 要求重新给 token，但以前已读成功 | 是否找到原工具；`config` 的来源和就绪状态 | 使用 P5 提醒复用，不重置已有凭据 |
| `self` 成功，`read` 返回 404 | 页面链接、工作区、具体页面访问授权 | 重新打开授权界面核对；404 也可能是无权访问，不要据此认定页面被删 |
| 401 / unauthorized | token 是否失效；环境变量是否覆盖了文件 | 经私密配置入口核对或轮换，不在聊天展示值 |
| 403 / restricted_resource | 连接能力和页面访问范围 | 核对 Read content 与正确页面；不直接授予全工作区 |
| 能找到标题，读不到正文 | 是否只执行了 `find` / `ls` | 用完整页面链接执行 `read`；标题搜索不是全文检索 |
| `truncated=true` 或存在未知块 | 正文长度、复杂块、子页面 | 缩小为一页简单记忆，必要时按授权范围逐页读取；本次不得声称全文完整 |
| 文件已在手机 Download，却无法执行 | 文件是否真正传入 Amoo 的执行工作区 | 重新走附件保存与哈希核验；Android 目录不等于 Amoo 工作区 |
| `node` 不存在 / 无执行工具 | 当前 Amoo 是否具备运行能力 | 记录限制，改用实际可用的集成；提示词本身不能安装工具权限 |
| 已经说过“记住”，新聊天仍没读 | 本轮是否真的调用工具 | 使用手动启动提示；自动召回与主动拉取分开验收 |
| 想让 Amoo 自动更新记忆 | CLI 是否包含写入能力 | 当前仅只读：先让它生成修改草稿，再由你在 Notion 更新 |

新版 CLI 保留 `self / ls / find / read / tree / db / init / config`。`find` 只按标题搜索；`tree` 默认只列直接子块，不能当作全文递归；分页命令有数量上限，出现 `has_more` 表示仍有后续。`init` 会写本地配置，因此“只读”指它的 Notion 内容能力，不是这个程序绝不写任何本地文件。

## 9. 维护记忆，让提示词长期可用

每次只保留对当前工作有帮助的内容。长期偏好与当前项目分开，临时测试另开一节。遇到冲突，以你当前明确要求为准，并让 Amoo 指出冲突，不静默覆盖长期偏好。

每次更新页面，同时递增版本和更换校验词。需要把新结论写回时，使用 [P8：记忆更新草稿](prompts.md#p8)，审阅后手动粘贴。此流程无需让只读 CLI 获得写入权限。

![图 6：手动启动、按任务读取、生成修改草稿、人工更新并复测](figures/06-daily-loop.svg)

撤销访问时，从 Notion 页面连接中移除该连接；如有凭据泄漏，按 Notion 官方入口轮换或撤销 token。撤权之后应再测试读取失败；不要把换一个页面链接当作凭据撤销。
