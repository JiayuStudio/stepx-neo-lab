# Step Studio 背屏宠物开发提示词

[研究所](../../README.md) / [开发工具与模板](../../sections/tools.md) · [先读开发实战](development.md)

下面是根据拓麻歌子 0.3.4 经验整理的可复制模板，**不是原始聊天逐字记录，也未逐条在全新 Studio 项目重跑**。建议一次发送一段，检查产物后再继续。真实背屏验收需要兼容手机和实际安装；网页预览只验证界面与图案。

## 1. 先识别项目和硬件通道

```text
请在当前 Step Studio 项目中开发 Neo 背屏宠物，名称为「拓麻歌子」。
先读取现有目录、入口、依赖和构建脚本，说明当前是网页预览、平台桥接还是原生 Android 项目，找到已有的背屏通道。
参考 https://github.com/JiayuStudio/stepx-neo-pet/tree/v0.3.4 和 https://github.com/stepx-advance/backscreen-toolbox ，核对许可与实际复用范围。
保留当前平台 bootstrap 和构建配置，不把第三方 StepX Neo Studio 客户端与本网页平台混为一谈。
如果当前环境不能直接访问硬件，请明确显示“预览模式”，并说明要补充的原生代码和构建条件，不能把模拟成功说成真机成功。
本阶段交付：目录与调用链说明、最小可运行项目。先验证一个简单背屏动画，再加入完整游戏。
```

## 2. 最小点阵与退出恢复

```text
请实现 Neo 的 17列×23行灰度点阵测试：391 个整数，每个 0～255，索引 y*17+x。做方框与 X 两帧交替，提供开始、停止和错误状态。
原生路径参考 RearDisplay.java，通过 getSystemService("display_ext") 获取服务，调用 setBackScreenAgentFrame(int[], Bundle)。先检查当前固件是否支持，不能假造接口或使用其他应用凭据。
播放前保存旧背屏模式，必要时临时设常亮；停止清帧，并在用户未另行改动模式时恢复旧值。异常退出后再打开也要可恢复。
网页预览展示同样的点阵数据，但单独标明是否连到真机。
交付合法帧校验与可用停止入口。验收需要背面实际出现方框/X，接口返回成功不能替代观察。
```

## 3. 可爱的双角色，别画成飞机

```text
将原始宠物替换为星跃和方跃，参考我提供的角色图片；如果当前项目没有图片，请明确缺少参考，先用文字特征完成可调整草图。
星跃：柔和星形身体、两只竖眼、短手脚。方跃：台阶形头顶、方眼、短手脚。两者都有可切换耳机造型。
为 17×23 灯阵专门绘制，主体先尝试约13×15，给耳机和上下移动留空间。避免过宽横臂，不能像飞机；不能直接缩小整张3D图来代替点阵设计。
使用整数像素，保留完整眼睛与轮廓，耳机不得遮眼，随身体同步移动。先交付静止、眨眼、上下移动一格的呼吸动画，再扩展开心、饥饿和睡觉。
提供逐帧点阵预览及原生使用的资源，尽量共用美术生成来源。验收检查每帧长度、亮度、越界和真实背屏可辨识程度。
```

## 4. 蛋、孵化与存档

```text
加入从蛋开始的成长流程：默认60秒，前50秒轻晃，50～58秒裂纹，58～60秒破壳，随后进入所选角色。
保存孵化开始时间，用时间差决定阶段；刷新、切后台或重开不能重置已完成的孵化。已有已孵化存档不能退回蛋。
正面和背屏读取同一份养成进度。角色、成长、性格、情绪、穿戴映射到动画；新照料动作播放短暂反馈，再回到常态。第一次载入存档不能重播历史动作。
交付前端与原生状态选择的对应关系，并验证跨阶段时间、重开恢复和切角色。不要靠页面定时器次数推进游戏时间。
```

## 5. 保留原生后台播放

```text
请保留或实现原生 Android 前台服务播放背屏，独立于正面 WebView 的定时器。用户主动开启，显示通知和停止入口，按目标 Android 版本配置服务类型和权限。
播放期间合理管理部分唤醒锁；停止时取消刷新、释放锁、清帧并恢复旧背屏模式。不要使用静音音频保活或主屏常亮。
分别显示送帧数量、宠物本体帧变化和错误状态，不能用角落标记闪烁假装宠物在动。
对可能存在的 Neo 后台冻结，只提供经当前固件确认的单应用设置方法和撤销方法；普通应用不能假装自行获得 shell 权限，不改全局冻结策略。
请列出锁屏验收步骤。服务运行或打包成功都不代表物理动画通过，更不能承诺永远后台运行。
```

## 6. 正面预览与安全区

```text
请优化手机正面界面：顶部导航避开状态栏与摄像头，底部按钮避开手势区，小屏可滚动。检查原生窗口是否已处理 insets，避免再次叠加留白；网页预览没有真实安全区时使用明确的预览适配。
分别识别浏览器模拟桥和真实原生桥，不能只凭 window.NeoNative 是否存在判断已连接手机。
正面角色与点阵保留相同的识别特征。验证眼睛未被3D几何遮挡、耳机同步移动、孵化状态与背屏一致。
交付窄屏预览和可安装版本分别检查的结果，未执行的项目标为待验。
```

## 7. 构建与真机验收

```text
请使用当前项目已确认的构建流程生成 APK，核对包名、版本、资源和签名兼容性，保留旧存档。签名私钥由既有安全构建流程使用，不加入项目素材。
先验证点阵每帧391个整数且亮度0～255，再安装到已授权的兼容手机。
真机检查：前台图案；切换角色与耳机；蛋的孵化；主屏关闭后至少两分钟宠物本体持续动作；停止清帧及恢复模式；重开保留进度。
没有连接手机时先完成构建与可复核代码，将真机项目保留为待验，不写“全部通过”。单独列出长期耗电、拔线深度待机、重启与固件兼容尚未验证的项目。
```

## 已有项目：只换角色，不破坏后台

```text
请在当前已能运行的背屏宠物项目上继续开发，只替换角色资源及必要的状态映射。
先读取现有原生服务、点阵驱动、显示模式恢复、存档和构建配置，保留这些已可用能力。不要改成只在网页 setInterval 播放的演示。
让新角色在17×23点阵中小一点、短手脚、眼睛清楚，给耳机和动作留边界。同步更新正面形象、孵化与穿戴资源，保持老存档兼容。
完成后给出修改文件、预览、构建结果和实际执行的真机验证；无法测试的项目明确待验。
```
